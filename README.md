# 宿舍团餐长 · Party Planner

> 八个人要吃一顿，光在群里问「哪天有空」就能问三天。
> 这个工具把门店、场次、人均、预算一次算完，最后给你一段**能直接粘进群里**的通知。

命令行工具 · 零第三方依赖 · 只读不写 · **绝不代替你下单**

## 一句话

**它不是点餐工具，是「组织者减负工具」。**

组织一次宿舍 / 班级聚餐，真正累的不是选餐，是这些事：

- 哪家店能办派对？能坐几个人？
- 哪天有场次？几点？
- 人均多少？超没超预算？
- 定下来之后怎么在群里说清楚？

前面三个问题查得到但散落在各处，第四个问题每次都要重新编。这个工具把四件事一次做完，并把最后一步的文案生成好。

## 快速开始

```bash
# 看效果（无 Token）
python tools/party_planner.py --demo

# 真实数据
set MCD_MCP_TOKEN=你的token
python tools/party_planner.py --city 上海 --people 8 --budget 80
```

### 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--city` | 城市名（模糊匹配） | 上海 |
| `--people` | 人数 | 8 |
| `--budget` | 人均预算（元） | 80 |
| `--date` | 期望日期 `YYYY-MM-DD` | 取最早可用日 |
| `--save FILE` | 存成 Markdown | — |
| `--demo` | 离线演示 | — |

> 需要 Python 3.9+。`tools/mcd_mcp.py` 是纯标准库 MCP 客户端。

## 用到了哪些麦当劳 MCP 工具

这一组（`party` 系列）是开放能力里比较少被用到的：团餐 / 派对预约。

| Tool | 用途 |
|---|---|
| `query-party-city` | 有哪些城市可办派对 |
| `query-party-store` | 该城市可办派对的门店 + 容量 |
| `query-partystore-date` | 该门店可选的日期与场次数 |

## 设计原则

### 只读不写

工具链里明明有 `party-order-create`，本项目**刻意不调用**。

理由：聚餐是多人决策，一键下单意味着「一个人替所有人做了花钱的决定」。工具应该止步于「把方案摆清楚 + 把话说明白」，最后点「确认」的必须是人。

### 参数自适应 + 暴露 schema

`party` 系列工具的入参名（`cityId` / `cityCode` / `partyStoreId` …）可能随迭代调整。本项目对每个调用按**常见命名轮次尝试**，第一次返回非空就用它。

同时——如果所有组合都失败，它不会假装成功，而是提示你运行：

```bash
python tools/mcd_mcp.py tools
```

直接看服务端真实的工具与参数 schema。**让用户能自己修，比藏一个报错有用。**

### 无网可用

任何一步失败都降级到 `--demo`，并打印失败原因。演示数据界面会标注「离线演示数据」，不冒充实时场次。

## 已知限制

1. **场次与价格依赖官方数据**，`--demo` 里的门店名、地址、价格都是演示值，不要当真实信息用。
2. 目前只选「第一家可办派对的门店」来查日期场次，不会遍历全部门店比价——因为多店遍历会打满 600 次/分钟的限流。
3. 人群标签（谁是素食、谁不吃辣）没有建模。这是刻意的：那是社交问题，不是排期问题。
4. **不代为下单**，也不锁座位。方案给出后需要自己到官方渠道确认。
